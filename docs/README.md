## 系统架构与端到端信号流

### § 3.1 系统架构总体概览

> **参考资源**：`tx_rx_end_to_end_signal_chain.drawio`、`system_architecture.drawio`

GNSS_RX 系统遵循发端 (TX) - 硬件链路 (RF) - 收端 (RX) - 后处理 (MATLAB) 的闭环设计。信号经历从数字生成、无线传输、数据采集、到离线分析的完整变换流程。

```
数字信号生成 (TX)
    │
    ├─ PRN 码生成 / 导航数据编码
    ├─ BPSK 扩频调制
    ├─ GNU Radio 流图驱动
    │
    ▼
硬件链路传输 (RF)
    │
    ├─ USRP 射频前端转换
    ├─ 物理信道传输 (线缆/OTA)
    │
    ▼
接收采集 (RX)
    │
    ├─ USRP 硬件采样
    ├─ 数据格式转换 (fc32 → sc16)
    ├─ 文件落盘 (.sc16 + .json)
    │
    ▼
离线分析 (MATLAB)
    │
    ├─ 数据加载与预处理
    ├─ 单/多卫星捕获
    ├─ 载波追踪与解调
    ├─ BER 计算与性能评估
    │
    ▼
评估报告与可视化
```

### § 3.2 端到端信号流详解（含数据类型）

#### 第一阶段：发端生成 (TX)

**1.1 发端初始输入**

系统通过配置文件和命令行参数驱动信号生成：

- **核心输入参数**
  - PRN 标识：`PRN ID` 或 `PRN 子集`
  - 导航数据：预定义的 GPS 导航电文 (`nav bits`)
  - 射频参数：采样率、中心频率、增益、带宽
  
- **配置机制**
  - 配置源：`configs/tx_*.yaml` 配置文件
  - 参数覆盖：`scripts/run_tx.py` 的命令行参数机制
  - 动态适配：支持实时调整输出特征

**1.2 扩频与基带生成（算法链）**

GPS L1 C/A 信号由伪随机码和导航数据调制而成：

- **PRN 码规格**
  - 标准：GPS L1 C/A (Coarse/Acquisition)
  - 周期：1 毫秒
  - 码长：1023 个码片 (chips)
  - 码率：1.023 Mcps (Mega chips per second)

- **导航比特处理**
  - 原始数据：二进制导航比特流
  - 归一化：映射到 $[-1, +1]$ 区间

- **基带 BPSK 调制**
  
  扩频操作遵循标准公式：
  
  $$s[k] = d[k] \times c[k]$$
  
  其中：
  - $d[k]$ — 导航数据（±1）
  - $c[k]$ — 伪随机扩频码（±1）
  - $s[k]$ — 扩频信号符号
  
  复基带信号表达：
  
  $$x[k] = A \cdot s[k] \cdot e^{j\phi}$$
  
  其中：
  - $A$ — 振幅
  - $\phi$ — 初始相位（理想零 IF 下 $\phi \approx 0$）
  - 能量主要分布在 I 轴，Q 分量接近零
  
  **工程实现**：虽然理想情况下 Q ≈ 0，但保留成对 IQ 复数形式，以适应后续的混频、滤波和 USRP 驱动接口。

**1.3 发射缓冲与 GNU Radio/UHD 互联**

GNU Radio 流图负责流式转换和硬件驱动：

- **基带缓冲管理**
  - 缓冲池：大段可循环回放的复数 IQ 样本缓冲
  - 重复模式：支持无限循环发射

- **GNU Radio 流图架构**
  ```
  vector_source_c (复数源)
        │
        │ fc32 格式
        ▼
  usrp_sink (USRP 硬件接口)
  ```
  
  - **`vector_source_c`** — 向量数据源块
    - 功能：流式输出预生成的复数 IQ 样本
    - 格式：`complex64` / `fc32`（32 位实部 + 32 位虚部）
    - 输出频率：由采样率决定
  
  - **`usrp_sink`** — USRP 硬件输出接口
    - 功能：接收基带信号，下发至 SDR 射频前端
    - 循环策略：与缓冲设置协同，确保连续无缝辐射
    - 时间戳：支持同步多天线发射（若系统配置）

- **UHD 驱动配置项**
  - `set_samp_rate(fs)` — 采样率设置 (Hz)
  - `set_center_freq(fc)` — 中心频率 (Hz)
  - `set_gain(gain_db)` — 射频增益 (dB)
  - `set_bandwidth(bw)` — 前端 ADC 带宽 (Hz)
  - `set_antenna(antenna_name)` — 天线口选择

#### 第二阶段：硬件链路与射频传播 (RF)

**2.1 硬件发射与射频传播**

USRP 基站将数字基带信号转为模拟射频信号并通过天线辐射：

- **信号转换链**：数字基带 (IQ) → DAC → 混频器 → PA 功放 → 天线

- **传输链路模式**
  - **线缆回环** — 通过衰减器直连，环境干净、干扰受控
  - **OTA (Over-The-Air)** — 真实空口传输，需应对多径、遮挡、干扰、频偏等物理限制

#### 第三阶段：接收采集与数据落盘 (RX)

**3.1 接收采集信号处理流水线**

> **流水线架构**：`usrp_source → head → Sc16CaptureSink`

这条轻量级 GNU Radio 流图用于可靠采集并持久化射频数据，是核心数据传输链路。

- **① usrp_source — 硬件采样源**
  
  | 方面 | 说明 |
  |:---|:---|
  | **职责** | 驱动接收机（如 B210）执行 ADC 采样与数字下变频，源源不断产出fc32 基带 |
  | **配置** | 从 `RxRuntimeConfig` 读取中心频率、增益、天线口等 |
  | **输出格式** | `fc32` (Float Complex 32-bit) — 32 位实部 + 32 位虚部 = 8 字节/样本 |
  | **样本速率** | 由 `set_samp_rate()` 决定，典型值 4 MHz |

- **② head — 采样门限网关**
  
  | 方面 | 说明 |
  |:---|:---|
  | **职责** | 采集固定样本数后自动停止，保护存储资源 |
  | **计算公式** | 样本数 $N = \text{sample\_rate\_hz} \times \text{duration\_s}$ |
  | **典型例** | 采样率 4 MHz，记录时长 2 秒 ⟹ $4 \times 10^6 \times 2 = 8 \times 10^6$ 样本 |
  | **输出** | 截断后的样本流 (fc32) |

- **③ Sc16CaptureSink — 落盘组件（自研）**
  
  将浮点基带转换为适合磁盘存储的整数格式，是数据落盘流程中的关键环节：
  
  | 步骤 | 操作 | 说明 |
  |:---|:---|:---|
  | 1 | 分解与限幅 | 提取 I、Q，并限制在 $[-1.0, 1.0]$ 区间以避免幅度卷绕 |
  | 2 | 放缩 | 乘以 32767，映射到 `int16` 的全值范围 |
  | 3 | 交织 | 内存排列为 `[I₀, Q₀, I₁, Q₁, I₂, Q₂, ...]` 形式 |
  | 4 | 落盘 | 采用小端序 (Little-Endian) 字节编码写入磁盘 |
  
  **输出特征**
  - 格式名：`SC16` (Signed Complex 16-bit)
  - 单样本大小：4 字节 (I 2字节 + Q 2字节)
  - 对比 fc32 节省：50% 磁盘空间和 I/O 带宽
  - 质量：在基带限幅良好的前提下，精度损失可接受

- **④ 元数据落盘（Sidecar JSON）**
  
  采集框架自动生成的配套描述文件 (`.json`)：
  
  | 元数据字段 | 说明 | 用途 |
  |:---|:---|:---|
  | `sample_rate_hz` | 采样率 | 时间和频率还原 |
  | `center_freq_hz` | RF 中心频率 | 频率映射、多普勒计算 |
  | `prn_id` / `prn_ids` | 单/多 PRN 标识 | 信号源识别 |
  | `all_prns` | 系统内所有可用卫星 PRN | 批处理参考 |
  | `chunk_size_bytes` | 数据块大小 | 重放缓冲分配 |
  | 其他 | 硬件信息、采集配置等 | 重现实验条件 |

#### 第四阶段：离线分析与性能评估 (MATLAB)

**4.1 本地计算与数据恢复**

采集完成后，通过 MATLAB 离线工作流进行信号处理和性能测试：

- **数据加载**
  - 函数：`load_gnss_rx_capture()`
  - 功能：透明加载 `.sc16` + `.json` 数据对
  - 输出：恢复为浮点复数基带 `fc32`

- **粗精捕获阶段**
  - 单星捕获：`run_prn_acquisition()` — 单个 PRN 的码相位和多普勒估计
  - 多星扫描：`run_multi_prn_survey()` — 系统内全可视卫星的快速扫描

- **追踪与解调阶段**
  - 载波追踪：分环追踪滤波器 (DLL、PLL)
  - 帧同步：导航数据帧边界检测
  - 比特解调：软判决或硬判决解调

- **BER 验证与性能评估**
  - 框架：`run_ber_loopback()` 闭环测试
  - 参考真值：`tx_truth.json` (发端端口的绝对参数快照)
  - 指标：符号级别、比特级别误码率；载波信噪比 (C/N₀)；定位精度
  - 输出：可视化报告与统计数据

## 数据类型与格式规范矩阵

系统流转跨越 Python 算法层、GNU Radio 中间件、UHD 驱动层以及 MATLAB 统计分析层。不同环节采用了适应场景的最优数据格式。

### § 4.1 全链路数据格式对照表

| 处理阶段 | 承载数据 / 文件名 | 类型与格式定义 | 样本大小 | 用途与备注 |
|:---:|:---|:---|:---:|:---|
| **信源** | 纯净 PRN CA 码 | `int8`，取值 $\{-1, +1\}$ | 1 字节/码片 | 扩频计算的最简整数形式 |
| **信源** | 纯净导航数据比特 | `int8`，取值 $\{-1, +1\}$ | 1 字节/比特 | 用于 BPSK 调制前的编码 |
| **TX 引擎** | 发送基带信号缓冲 | `complex64` (`fc32` 标准) | 8 字节/样本 | 浮点复数，计算动态范围大 |
| **UHD 链路** | 主机 ↔ USRP 传输 | `sc16` (Short Complex 16-bit) | 4 字节/样本 | 物理总线首选，50% 带宽节省 |
| **RX 采集** | 落盘捕获文件 `.sc16` | `iq_int16_interleaved_le` | 4 字节/样本 | I/Q 交织，小端序 |
| **RX 配置** | 元数据文件 `.json` | 标准 JSON 文本 | — | 采集参数、硬件配置快照 |
| **测试参考** | 发端真值文件 `tx_truth.json` | 标准 JSON 文本 | — | 参考参数：相位、PRN、调制方式等 |
| **分析输出** | MATLAB 测试报告 | `.png` 图表 + `.mat`/`.json` 数据 | — | 测试总结、结果归档与问题回溯 |

### § 4.2 数据格式选择的工程考量

#### 为何在 TX 和内部计算中使用 `fc32` (Float Complex 32-bit)？

- **动态范围宽**：浮点数自动处理溢出和下溢，无需手工限幅
- **算法友好**：三角函数、FFT、滤波等数学运算对浮点数优化充分
- **精度充足**：32 位单精度足以满足 GPS 信号处理精度需求
- **工具支持**：Python NumPy、GNU Radio、MATLAB 都原生支持

#### 为何在 UHD/存储层使用 `sc16` (Short Complex 16-bit)？

- **带宽节省**：相比 fc32 节省 **50%** 线缆和磁盘 I/O
- **精度可控**：在基带严格限幅前提下，保留 16 位整数精度足够
- **硬件支持**：USRP UHD 驱动原生高效支持 `sc16` 格式
- **存储优化**：一个小时的 4 MHz 采样仅需约 28.8 GB（相比 57.6 GB）

#### 小端序 (Little-Endian, LE) 的选择

- Linux/Windows 主流处理器（x86/x64、ARM）均采用小端序
- 便于直接内存操作和快速 I/O
- MATLAB、Python 在小端序系统上读取 `int16` 数组最高效

## 核心操作命令与复现指南

本节分三个阶段呈现实验操作：自检验证、真实硬件采集、离线分析。

### § 5.1 第一步：环境自检与验证 (Dry-Run)

**目的**：验证 Python 环境、配置文件结构、硬件驱动包无误。**无任何实际RF信号发射或设备占用**。

**命令**：
```bash
cd /home/shen/projects/GNSS_RX
PYTHONPATH=src python3 scripts/record_rx.py --dry-run
```

**预期输出**：
- Python 各依赖包成功加载
- 配置文件格式正确解析
- 目录结构检查通过
- USRP 驱动可初始化（连接与否均可）
- 过程无异常退出

**常见问题排查**：
- `ModuleNotFoundError`: 检查 `PYTHONPATH=src` 是否正确
- 配置解析错误：检查 YAML 文件缩进和格式

### § 5.2 第二步：真实硬件信号采集

**目的**：利用实际 USRP 硬件执行真实的 RF 波形采集。

**命令**：
```bash
cd /home/shen/projects/GNSS_RX
PYTHONPATH=src python3 scripts/record_rx.py --config configs/rx_prn1_capture.yaml
```

**配置文件说明** (`configs/rx_prn1_capture.yaml`)：
- 采样率、中心频率、增益：RF 前端参数
- 采集时长、输出路径：数据存储
- PRN 标识：单 PRN 或多星选择

**预期输出**：
- 硬件初始化成功并开始 ADC 采样
- 实时显示采集进度
- 完成后生成 `.sc16` 和 `.json` 文件对

**输出文件**：
- `.sc16` — 原始 IQ 数据 (小端序 int16 交织)
- `.json` — 采集元数据 (采样率、频率、PRN 等)

**调试技巧**：
- 检查 USRP 连接：`uhd_find_devices`
- 监测增益范围：`--gain 30` (dB)，避免超出硬件范围
- 长时间采集：增加 `--duration` 但要注意磁盘空间

### § 5.3 第三步：合成数据模拟（无硬件模式）

**目的**：在无 RF SDR 设备的环境下，用软件合成 GPS 信号进行完整链路验证。

**命令**：
```bash
cd /home/shen/projects/GNSS_RX
PYTHONPATH=/home/shen/projects/gnss_tx/src:src \
  python3 scripts/gen_synthetic_capture.py \
  --snr-db 10 \
  --duration 2
```

**核心参数说明**：
| 参数 | 含义 | 典型值 |
|:---|:---|:---|
| `--snr-db` | 信噪比 (dB) | 5~15 dB (弱至中等信号) |
| `--duration` | 采集时长 (秒) | 1~10 s |
| `--output-dir` | 输出目录 | 当前目录或 `results/` |

**预期输出**：
- 合成 GPS 信号并叠加 AWGN 噪声
- 生成标准 `.sc16` + `.json` 文件对
- 可直接输入 MATLAB 分析流程

**应用场景**：
- 大学教学、算法开发（无需硬件成本）

### § 6.2 常见问题与快速排查

| 问题 | 可能原因 | 排查步骤 |
|:---|:---|:---|
| `PYTHONPATH=src` 命令失败 | 路径不正确或权限不足 | 检查当前工作目录；运行 `pwd`；确保 `cd /home/shen/projects/GNSS_RX` |
| USRP 硬件无法连接 | 驱动未安装或硬件未在线 | 运行 `uhd_find_devices`；检查 USB/网络连接 |
| 采集文件过大 | 采时时长或采样率设置过大 | 减少采集时长、降低采样率或启用数据压缩 |
| MATLAB 读取失败 | JSON 格式错误或文件损坏 | 手工检查 `.json` 文件；重新采集 |
| BER 异常高 | 信号链路问题、参数设置错误、真值文件不匹配 | 检查 SNR；验证配置参数；确保使用正确的真值文件 |

### § 6.3 开发与集成建议

- **模块化开发**：各个功能模块（采集、处理、分析）应独立可测试
- **配置驱动**：使用 YAML 配置文件而非硬编码参数，便于复现和扩展
- **文档同步**：修改代码时同步更新对应的文档注释和技术文档
- **版本控制**：采集数据、采集配置、分析结果应妥善版本控制，以便复现
- **自动化测试**：利用合成数据进行 CI/CD 自动化测试，提高代码质量
